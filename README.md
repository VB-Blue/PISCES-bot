## v0.13.6 历史更新

2026-10-06 v0.13.6 修复“继续”一直返回 HTTP 409：
- 任务进行中关闭应用后，核心里那一轮会一直停在“进行中”，之后每次“继续”都被拒绝。现在应用启动后第一次开始任务前，会让核心结束上次遗留的轮次，没做完的那一步记为“结果未知”。
- 核心（`D:\记忆体`）对“结果未知”的步骤：允许继续这件事，但不允许原样重放那一步，需要先检查实际情况。旧轮次的未知步骤不再让之后正常完成的轮次也被标成“结果未知”。
- 模型把“更新计划”和“读取环境”放在同一批时，不再提前并发读取（之前会撞上核心“有写操作正在进行”的规则而 409）。
- 核心拒绝时显示原因码，例如 `核心返回 HTTP 409（work_turn_in_flight）`。
- PowerShell 命令分级：只查看文件、版本或环境的只读命令标为低风险，可选“本次对话内不再询问只读命令”或“永久允许 只读命令”（可在 设置 → 本机能力 撤销）；会写入、删除、移动、安装、联网、运行脚本文件或启动程序的命令仍为高风险，每次都要确认。判断不了的一律按高风险处理。
- 新增 `write_document`：直接生成排好版的 Word 文档（标题居中、黑体小标题、正文首行缩进），保存后读回核对字数和标题数。写文档不再需要拼 Python 脚本、安装 python-docx、另写核验脚本。实测“写一篇果蝇论文”原来用了 17 次模型调用、约 26 万 token。

## v0.10.0 PISCES AI主体：LLM 始终是工具

PISCES AI自己负责每件事的全过程，LLM 只是它调用的工具之一（`electron/subject/`）。这是 `D:\记忆体\PERSONAL_BEING_ARCHITECTURE.md` 里“模型只是器官”的落地，第一次真正接进了实际任务流程。

```
用户的话 → 主体：理解 → 回忆 → 决策 → 交给执行者 → 自己核对 → 纠错 → 学习
```

- **理解**：把请求解析成目标、交付物、可机械核对的完成标准、需要的软件和参数。以前核对成功过的同类请求由主体在本地认出、直接复用，不问模型；没见过的才调用 LLM 的“理解”工具，回答必须通过格式校验。
- **决策**：有对得上、参数齐全、战绩可靠的软件技能，就在本地回放，不调模型；否则调 LLM 的“规划”工具拿到带验收标准的计划，再交给执行者（LLM 加本机工具）去做。闲聊和简单问答不进任务流程。
- **核对**：主体自己检查完成标准，不信执行者的自述：文件是否在本次任务期间出现、里面有没有该有的内容、回答里有没有该有的内容。只有代码检查不了的，才请 LLM 的“核对”工具对着证据判断。没通过就带着失败原因重新规划、再做一次；还不行就如实报告还差什么。
- **学习**：每件事都记下种类、走的路线、是否通过核对、用了几次模型（`memory/subject.json`）。同类任务优先选过去有效的做法。用软件做成的事，主体会自己把步骤存成技能。
- **看得见**：回答下方标明“✅ PISCES AI已核对 / 用本地技能完成 / 认出是做过的事 / N 次模型调用”。「学习记录」新增“PISCES AI主体：自己完成了多少”，显示接手的任务数、核对通过数、本地处理数、平均每件事的模型调用次数，以及最近任务的核对结果。
- 测试 `tests/subject.test.cjs`：主体理解、规划、交出执行、自己核对文件；执行者谎称完成时被核对抓住，然后重新规划再做；同一件事第二次在本地认出、用技能执行、本地核对，全程 0 次模型调用；闲聊不进任务流程，理解失败时退回普通回答。
- 评测默认走主体，`npm run eval -- --loop` 可以用旧的 LLM 主循环跑同一批任务做对比。设置里的 `subject: false` 可以关掉主体（界面冒烟测试会关掉它）。

还要说清楚的限制：遇到从没见过的任务，理解和规划仍然来自 LLM 工具；主体负责的是了解用户、管住任务、核对结果和积累经验。重复的事会越来越多地在本地完成，“本地处理”和“每件事的模型调用次数”就是衡量它是否在变得更自主的指标。这一版还没有用真实模型跑过评测。

## v0.10.0 方向调整：先让助手真正聪明

之前的版本一直在对照竞品补功能，但真实使用记录显示：一共 5 轮对话，修图和整理邮件都在反问用户，新闻汇总被“访问网站”确认卡了 1.5 小时，记忆里 0 条内容。所有测试都用脚本化的假模型，从没量过助手在真实任务上办成了几件。这一版把重心放回“聪明、懂用户、能把事做完”，并开始用真实模型量。

**新的大脑**（`electron/brain.cjs`）
- 系统提示从“受限的 AI 工作者”改成“用户本人的长期私人助手”：先读懂真实意图，模糊时按最可能的意思直接做并说明假设，只在代价高的歧义、需要用户私人信息、不可逆动作时才问。
- 写明做事方法：信息不够先查不编、独立的调用并行发出、每步看结果、3 步以上先列计划、结束前自检、汇报先给结果。

**懂用户：用户画像**
- 新增一份持续更新的“用户画像”（`memory/profile.md`），每轮回答前都会读。每轮对话结束后，学习器会结合最近几轮对话和用户的反应（催促、纠正、表扬）更新画像，推断出的内容标“（推测）”。
- 「记忆 → 我眼中的你」可以查看、修改画像，也可以撤销上一次修改；回答下方出现“更了解你了：…”时也可以一键撤销。带密码、密钥的改写会被拒绝。

**长任务**
- 上下文超过约 15 万字符时，较早的工作过程会被压缩成“工作记录”（目标、已完成、关键事实、失败过的方法、下一步），任务继续往下做。原始请求不会被压缩掉。
- 后台任务把工作记录存进任务本身：被中断、暂停或失败后点“继续”，会从工作记录接着做。对话上限提高到 100 步，后台任务 200 步。
- 之前对话的每一轮会带上“这一轮实际执行的操作”，说“继续”“再加一列”时助手知道真实进度。

**去掉卡住助手的地方**
- 每一轮都走能力最强的本地代理路径；只有手动选定软件窗口、或没有配置 AI 时，才走核心工作单（不再出现 8 次调用额度用完导致的 409 中断）。
- 读取公开网页不再逐站确认；只有网址里带着较长的不透明参数（可能把信息带出去）时才先问。
- 默认最大输出从 8192 提高到 32000（旧的默认值会自动迁移）。思考型模型把额度全用在思考上时，自动加大额度重试一次；服务拒绝过大的值时逐步减半，不会再回到被拒绝的大小。
- `update_plan` 不再算作“软件控制”，关闭软件控制后计划清单照常可用。
- 空回复分三种情况处理，靠用量数字区分：服务端偶发故障（普通长度的输入只回了 1～2 个词元）原样自动重试最多 3 次；上下文满了（输入极长）先压缩再重试；思考把额度用完则加大额度、提示少想再重试。之前它们都被误报成“思考用完了额度”。实测当前使用的中转服务大约每 3 次请求就有 2 次落到一个坏掉的上游通道（约 60 秒后返回 1 个词元的空回复），这很可能是以前频繁出现空回复的主要原因。
- 网关超时等 5xx、断网：只有一个服务可用时，原地重试 2 次再报错（例如评测中遇到的 HTTP 524）。

**更会用工具**
- 允许模型在一轮里同时发起多个工具调用（以前只有开了子代理才允许），单轮最多 32 个。同一轮里的搜索、读网页、读文件等只读查询会并发执行。
- 新增 `news_search`：从必应资讯的 RSS 拿新闻，返回真实原文链接、来源媒体和发布时间，按时间从新到旧排列，可以按天数过滤。之前查“昨天的科技新闻”只能抓普通搜索页，结果大多是百科和网站首页，模型还会自己猜文章网址。
- 提示词新增：搜索摘要只是线索，重要事实要打开原文核实；不要猜网址；两种理解都说得通、又都容易给出时，两种都给。

**软件技能：越用越快，不依赖模型的那部分能力**
- 助手用软件成功做完一件事后，可以用 `save_skill` 把这一轮里真正生效的操作保存成“软件技能”：没起作用的尝试会被丢掉；按钮靠类型、名称和 UI Automation 编号识别，不靠会变的序号；会变化的内容（输入的文字、文件名）变成参数。
- 下次同类任务，“相关记忆”里会列出对得上的技能，模型用 `run_skill` 在本地回放：每一步都会核对界面有没有按预期变化，整个过程不调用模型。哪一步对不上就停下，返回“卡在第几步”和当前界面，由模型从那里接着做。
- 每个技能都记录成功和失败次数；失败远多于成功的技能不再推荐。「记忆 → 软件技能」可以查看步骤、参数、战绩，也可以删除。
- 这是本地大脑的第一块：模型没有的、关于“你的软件怎么操作”的程序性记忆，换模型也照样能用。测试 `tests/skills.test.cjs` 用模拟的记事本覆盖了录制、存成技能、换参数回放、界面对不上时交回模型、失败多的技能不再推荐。真实软件上的回放要等桌面评测。
- 评测新增两个软件任务（`npm run eval -- --desktop`，运行时请不要操作电脑）：用记事本写清单并保存，第二次在新对话里靠技能完成，并比较两轮的模型调用次数；用计算器算数。

**为本地大脑积累经验**
- 每一轮（对话、后台任务）的完整轨迹写入 `memory/trajectories/<年-月>.jsonl`：请求、用到的记忆、每次工具调用的参数和结果、最终回答、模型与用量；赞/踩和纠正也记进去。数据只留在本机。这是之后本地大脑“影子学习”的原始经验。

3. 到「记忆 → 我的偏好」填写称呼、习惯、目标和边界，保存到核心。每张工作单冻结档案版本，工作者不能修改档案。`USER.md` 是可导出的视图，修改导出文件不会更改核心。
4. 在「核心 + AI」选择 UTF-8 文本文件，要求“生成所选文件清单和校验”。模型获得文件 ID，核心执行读取、生成新清单并校验；原文件不覆盖。
5. 在对应对话查看调用、操作步骤与产物；「任务」只保存明确创建或从对话加入的持续事项，支持暂停、恢复与完成。到「学习记录」选择新文件，点击独立复做，这条路径不调用模型。

## 工作与学习

每轮先取得绑定用户与会话的主体回执，再签发工作单。每次模型请求前向核心预留额度；工具提案回到核心执行，失败反馈进入下一轮模型请求。勾选“规划 / 执行 / 审阅”可让同一服务的三个工作者顺序协作，共用档案和预算。规划者和审阅者没有执行权限，审阅意见仍是模型建议。当前没有开放的后台 agent 池或自动跨服务派工。

模型工具包括 `read_file`、`write_inventory`。本轮用户明确授权选定软件窗口后，执行者还获得 `observe_desktop` 和 `desktop_action`，可以观察真实控件、逐步点击、绑定输入框输入文字及使用少数编辑按键。每次动作前重新观察，核心检查目标、角色、有效期和风险，进入原有主体图、合约、持久化派发与回执链。失败反馈返回 AI，无法确认交付结果时停止自动执行。模型自由文本仍待验证。

学习限定于“读完所选文本 → 生成并校验清单”。从实际成功序列提取参数化步骤，复做消费保存的程序并绑定新文件。3 组不同内容、至少一次核心独立复做且无反例后，方法标记为验证通过。相同内容换文件名不增加独立输入数。失败方法限制复用，删掉保存的步骤后不能继续复用。此结果不证明通用推理、任意方法创造或人类智力。

暂停“经验采集”只暂停桌面记录，核心继续保存对话、任务审计和操作反馈。没有周期付费研究；学习成绩不按聊天或记忆条数计算。

## 范围与成本

- 每轮核心工作单最多 8 次模型调用、16 个工具步骤、10 个文件，提取的单个正文最多 48 KB。
- 模型上下文上限 120000 字符，输出设置 `max_tokens: 4096`，触顶截断时在回复末尾提示；缺少用量字段显示“未知”。
- 只有用户选中的文件在模型提出读取后发送给该服务；不上传整个核心记忆，只提供有限确认事实摘录。
- 产物只新建于 runtime 的 `assistant_artifacts/<work-id>/`，检查目录重定向并读回校验。
- 核心鉴权失败或回执不匹配时，阻止模型调用；核心令牌不传给模型。
- 重启中断标为结果未知，不自动重放操作。

## 让 AI 操作软件

先打开要操作的软件，再回助手点击「选择当前软件」。核对窗口标题和进程，勾选本轮授权后发送具体目标。界面文字仅交给授权时配置的 AI 地址和模型；不上传截图。工作单绑定真实 PID/HWND，最多 12 个底层动作、5 分钟，仍受 8 次模型调用和 16 个工具步骤限制。运行时助手最小化，任务结束或出错恢复。切换窗口、观察过期或界面变化会阻止动作；无可用 UIA 控件时明确失败。

语义点击、绑定文本输入和有限编辑快捷键已实现。坐标、拖拽、滚动和跨窗口选择尚未接入 AI 工具。删除、发送、支付、提交等动作停止，本版本未提供 AI 高风险动作的一次性审批界面；终端、认证、密码管理和安全设置不在自动化范围内。

操作经历保存于原有主体工作单，包含 AI 提案、前后状态和失败原因。通过真实验证的语义点击进入现有 `computer_use_routines` 候选库，并通过原有核心的同结构界面绑定路径复用。文本输入目前是经历记录，未证明能自动提取完整新流程；重复点击成功也不等于跨软件泛化。

运行 `npm run smoke:desktop` 可启动独立临时核心与专用 WPF 测试程序，测试真实输入和点击。教师是本地确定性模拟服务，付费模型调用为零；这验证工具与反馈链，不能作为真实 LLM 任务理解或通用智能成绩。

## v0.5.0 本机能力、记忆与界面

**AI 能做什么**（设置 → 本机能力，或「桌面控制」页，可逐类开关）：联网搜索与读网页、查看/读取文件、写入文件、执行 PowerShell、启动软件与网址、设置提醒（含每天/每周重复）。两种模式（智能助手 / 直接 AI）都可使用；核心不在线时普通对话自动降级为直接 AI。

**安全边界**：
- 读取桌面/文档/下载和你添加的文件夹是自动的，其他位置先问；`.ssh`、浏览器登录数据、应用私有目录一律禁止。
- 写文件、执行命令、启动软件、访问陌生网站都会弹出确认（写文件与命令每次都问）；危险命令（格式化、改注册表、关机、`iex` 等）直接禁止，不能写入 exe/bat/ps1 等可执行文件。
- 网页抓取禁止访问本机和内网地址，网页与命令输出被当作数据而不是指令。
- 本机操作的步骤和结果显示在对应对话，另有本机 `tool-audit.jsonl` 审计记录（含被你拒绝的）。这些通用工具不经过核心的合约链，其审计记录不是核心回执。

**越用越懂你**（本地保存于用户目录 `memory/`，全部可见、可改、可删）：
- 长期记忆：AI 通过 `remember` 记录偏好/事实/习惯/目标；每轮结束后可自动整理（设置 → 通用，默认开，多一次很短的请求）。回答下方显示“记住了……”并可撤销。
- 经验手册：多步骤任务成功后总结做法；类似任务出现时作为参考注入。
- 反馈：回答下方“赞/踩”。“踩”加一句原因会成为长期遵守的纠正；“赞”提高所用经验的权重。
- 每次回答会标明参考了哪些记忆；对话原文建立了可搜索索引，AI 可用 `recall` 回忆“上次说过的事”。
- 这是检索与总结式的学习，效果取决于所用模型；它不等同于核心的“独立复做验证”，两者在界面里分开显示。

**界面**：移除演示模式与占位卡片；对话可重命名、可按内容搜索；提醒支持指定时间、每天/每周重复、删除记录；设置新增服务预设、连接测试、模型列表；关闭窗口行为与开机自启可选；任务/记忆/学习/桌面控制页重做为可读的列表而不是原始 JSON。

验收：`npm test`（含记忆与工具的单元测试）、`npm run smoke`、`npm run smoke:ui`（用脚本化模型驱动真实界面：工具调用、审批弹窗、拒绝、记忆、各页面、提醒、设置）。

## v0.6.3 把“怎么干活”的思路带进来

你在 Outlook 里试出的问题：AI 做了 8 步（找窗口、截图、读控件、搜索）后，核心的 8 次模型调用额度用完，返回 HTTP 409，任务直接中断，邮件一封没处理。

- 核心拒绝继续调用（409 等）时，已经开始的本地任务改用本地计数继续，不再中断；结束时核心结算失败也不再把已完成的工作判为失败。
- 给控制软件的任务加入固定的工作方法（写进系统提示）：先弄清目标和完成标准；先看再动，小字用 `zoom` 放大；标准界面用控件树读列表内容（邮件主题、发件人）来判断，而不是只看图；复杂任务先 `update_plan` 列计划并持续更新（聊天里可见）；优先控件编号 > 快捷键 > 菜单 > 坐标；每个动作后复查，没变化就换办法，同一做法最多试两次；批量操作先试一项再成批；不可逆操作先确认，可撤销操作（归档、移动）直接做；做完核对并汇报。
- 新增 `zoom`（放大截图局部）和 `update_plan`（可见的任务清单）；`inspect_window` 可读至 500 个控件，并支持按文字过滤。

## v0.7.0 通用的软件控制层（用代码，而不是提示词）

之前靠系统提示告诉模型“要先看、要复查”，模型做不到就白搭。现在这些都由代码保证，对任何软件通用（`electron/control-tools.cjs` + `desktop-agent.cjs`）：

- **标记式观察（set-of-marks）**：`observe` 用 UI Automation 取出窗口里所有可操作控件，在截图上画框并编号，同时返回元素清单（类型、名称、当前值、选中/勾选状态、是否可用）。模型直接说“点 12 号”，不用估像素坐标。
- **每个动作自带验证**：click / type_text / press_keys / scroll / drag 执行后，代码会等界面稳定（画面不再变化）、对比操作前后画面得出 `changed`，并自动返回新的标记截图。模型不会在不知道结果的情况下继续盲操作。
- **跟随弹窗**：操作打开了同一程序的新窗口或对话框，后续操作自动切到它。
- **代码级刹车**：同一操作连续 2 次没有界面变化就被拒绝；连续 6 次任何操作都无变化也被拒绝，要求模型停下来向用户说明。
- **没有控件的界面**：`find_text` / `click_text` 用 Windows 自带 OCR 找屏幕上的文字并点击，覆盖 Photoshop 这类自绘界面。
- **读内容**：`read_window_text` 按控件树阅读顺序读出列表项、文档正文、标签（TextPattern/ValuePattern），不靠看图猜。
- **等待**：`wait_for` 等文字出现/消失或窗口出现，代替盲等。
- **输入**：`type_text` 可指定输入框编号，优先直接设置控件内容，失败自动改为聚焦 + 全选 + 粘贴；`submit` 可顺带回车。
- 另有 `zoom`（放大局部）、`update_plan`（可见的任务清单）、`inspect_window`（原始控件树，可过滤）。

在真实的 Windows 计算器（UWP，没有任何针对它的代码）上实测：`launch_app` → `observe` → 按编号点 七、加、八、等于 → `read_window_text` 读到“显示为 15”。测试 `tests/desktop-agent.test.cjs` 用真实 WPF 窗口覆盖：编号点击、按编号输入、列表选择、复选框、OCR 点击、等待、读文字、放大、计划、禁用组合键、以及循环刹车。

## v0.8.0 多代理（子代理）

主代理可以把互相独立的子任务交给子代理（`delegate` 工具），自己继续做别的，最后汇总：

- **并行**：模型在同一轮里一次发起多个 `delegate`，它们同时运行（同时最多 3 个，排队执行其余的；每轮最多 8 个）。
- **能力受限**：每个子代理按需要拿到能力组——`web`（联网）、`files`（读写文件、修图）、`desktop`（启动并控制软件）、`shell`（命令）。它拿不到 `delegate`（不能再派生）、`remember`/`save_playbook`（不能改你的记忆）。
- **屏幕只有一个**：带 `desktop` 能力的子代理通过互斥锁排队，同一时间只有一个在操作屏幕；每个子代理有自己独立的控制状态（目标窗口、控件编号、防循环计数）。
- **授权不绕过**：子代理用的是同一套授权。弹窗标题会带上子代理名（如“[邮件整理员] 让 AI 控制 Outlook”），永久授权、审计记录与主代理共用。
- **看得见**：聊天里的步骤列表显示“子代理：名字”，子代理的每一步以 `[名字] …` 出现；“停止”按钮和 Ctrl+Alt+Q 同样会中止所有子代理。
- **可调**：设置 → 本机能力 → “子代理（多代理协作）”可关闭；“子代理使用的模型”可填一个更便宜更快的模型，留空则同主模型。
- 子代理的汇报被当作待核实的信息：提示词要求主代理对重要结论自己核对。
- 与原有“规划 / 执行 / 审阅”勾选项不同：那个是核心工作单里同一件事的三个角色；`delegate` 是把不同的事拆开并行做。

测试 `tests/subagents.test.cjs`：真实的主/子代理循环对脚本化模型——两个子代理确实并行（同时在途 ≥ 2）、各自只有受限工具、步骤带名字回传、审计共享；屏幕互斥锁按顺序；每轮上限、无确认通道时拒绝、授权标题带子代理名。

## v0.8.1 多个 AI 服务 + 多代理分工

**多 API 配置**（设置 → AI 服务）：
- 可保存多个服务（地址、模型、密钥各自加密保存），为每个服务标注“擅长”（强推理 / 速度快 / 便宜 / 能看图 / 擅长代码 / 长文本）和备注，设置同时最多几个代理使用它。原来的单个服务启动后自动变成“默认”档案，无需重配。
- 输入框旁的下拉框可以为当前对话选用某个服务；不选则用默认。
- **自动切换**：当前服务欠费（402）、限流（429）、5xx、断网或密钥失效时，同一次任务改用下一个服务继续，步骤里会显示“切换服务：A → B”。只有这类服务端问题才会切换，请求本身有误（400 等）不会换服务重试。某个服务可勾掉“参与自动切换”，它就不会收到别的服务的对话内容。
- **控制软件的任务不切换、不分流**：授权时的 AI 地址与模型就是唯一会看到界面文字的服务。

**多代理分工**（设置 → AI 服务 → 任务分配）：
- 主代理派工时可选角色模板：资料员 / 程序员 / 操作员 / 写作员 / 复核员，各自带默认工具和适合的模型类型；也可用 `profile` 直接点名某个服务，或 `prefer` 指定偏好。配置了多个服务时，服务名称、擅长和备注会写进 `delegate` 工具说明，让主代理知道怎么分配。
- 分配顺序：点名的服务 → 你在“任务分配”里给该角色指定的服务 → 需要看屏幕的交给能看图的服务 → 擅长该类任务的服务 → 默认。规划者、审阅者、记忆整理也可各指定服务；记忆整理在没指定时，会优先用标了“便宜”的服务。
- 每个服务有并发上限，超出的代理排队，避免触发某家的限流；先在服务上排队、再占全局 3 个并行名额，所以排队不会挡住用别的服务的代理。
- 子代理的汇报会写明实际使用的服务、分配依据和发生过的切换；授权弹窗标题为“[名字·服务] …”。

测试 `tests/routing.test.cjs`（档案保存与密钥保留、路由优先级、切换条件、并发排队、真实 HTTP 服务上的故障切换、软件任务不外流、规划/审阅分服务、子代理分配）；`npm run smoke:ui` 新增“默认服务失效 → 备用服务回答”的整界面流程。升级后需 `npm run pack:core` 重新打包，启动器才会用上新版本。

## v0.9.0 个人助手：后台任务、连接器、可撤销的改动、人设与新界面

对照 Meta Muse 这类个人助手补齐的能力（本机实现，不依赖云端虚拟机）：

**后台任务**（侧栏“后台”）：
- 交给助手一件事然后离开：马上开始、定时开始（1 小时后 / 今晚 / 明早 / 自定义），或每小时 / 每天 / 每周重复。对话里说“这个放到后台去做”，模型也会调用 `background_task`，创建前会先问你。输入框里 `/后台 …` 可直接创建。
- 运行中能看见逐步进展，能补充指令（下一步生效）、暂停、继续、取消。需要授权的操作会等你确认，并弹系统通知、侧栏和顶部提示；30 分钟没回复按“拒绝”。应用重启时进行中的任务标为“被中断”，**不会自动重放**，由你点“继续”。
- 同时最多 2 个后台任务运行。屏幕只有一个：所有要操作软件的代理（对话、后台任务、子代理）通过同一把屏幕锁排队。Ctrl+Alt+Q 同时停止对话和所有后台任务。
- 关闭窗口时留在托盘，后台任务和定时任务继续。**电脑关机或应用退出时不会运行**（这是和云端助手的根本差别）。

**改动记录与撤销**：助手每次创建、覆盖或修改你的文件前，都先保留原件（20 MB 以内）。“后台 → 改动记录”可一键撤销；如果文件在那之后又被你改过，会拒绝撤销，避免覆盖你的内容。新增 `edit_text`（精确替换，比整份重写安全）和 `search_text`（按内容搜索）。

**连接器**（侧栏“连接器”）：接入 MCP 服务（GitHub、Notion、数据库等，stdio 方式）。每个连接器有权限档位：**只读**（改动类工具根本不提供给 AI）/ **改动前确认** / **自动**（标记为可能删除的仍会问）；每个工具还可单独设为 始终允许 / 每次询问 / 禁用。工具是否只读以服务自己的声明为准，没声明的按“会改动”处理。环境变量（令牌）加密保存、不再显示。对话、后台任务、子代理（`connectors` 能力）都使用同一套权限。

**助手人设**（设置 → 助手）：名字、头像、主题色、说话风格（均衡 / 简洁 / 温和 / 专业 / 轻松 / 自定义）。名字和风格会告诉 AI；头像和主题色改变界面。

**界面**：
- Ctrl+K 命令面板：跳转页面、新建任务、切换本次对话用的服务、切换主题、搜索最近对话。
- 子代理的步骤按“人”分组显示，标出各自使用的服务；服务切换有单独的提示样式。
- 欢迎页按时段问候，新增“交给后台去做”“连接外部服务”入口；输入框 `/` 快捷命令（`/后台`、`/记住`）；回答可朗读。
- 浅色 / 深色统一的配色体系，主题色跟随助手人设；后台任务、连接器、命令面板和改动记录都是新页面。

**没有做的**（与 Muse 的差距，如实说明）：云端虚拟机（关机后继续跑）、助手自己的收件邮箱、语音输入、智能眼镜、视频头像、商家与支付伙伴集成。其中商家与支付类动作也刻意不做自动执行：涉及付款、发送、删除的步骤仍然停下来问你。

测试：`tests/capabilities.test.cjs`（检查点与撤销保护、精确编辑、内容搜索、连接器权限三档与工具级覆盖、后台任务的审批 / 补充指令 / 暂停 / 重启中断 / 定时重复 / 并发上限）；`npm run smoke:ui` 新增整界面流程：人设生效、命令面板、真实连接器进程、AI 通过连接器读取、后台任务请求确认并写文件、改动记录里撤销、深色主题。

## v0.9.1 对话记录不再丢失

左侧对话记录以前只存在页面的 localStorage 里：有容量上限、退出时才异步落盘，进程被强制结束就丢。现在由主进程把对话写进 `workspace.json`（用户数据目录），原子写入，并保留上一份完好副本 `workspace.json.bak`；关闭窗口时同步写一次，退出前再补写一次，文件损坏时自动用备份。旧版留在 localStorage 里的对话会在第一次启动时自动迁移。测试：`tests/workspace-file.test.cjs`，以及界面冒烟里“清掉页面存储后重启仍能恢复对话”。

打包输出改为 `release/pisces-ai-v0.10.1/win-unpacked/`，`启动 PISCES AI.cmd` 会优先使用它。旧的 `assistant-v0.8.0` 目录可能因打包时程序仍在运行而不完整，可在关闭所有“PISCES AI”窗口和托盘图标后删除。重新打包前请先完全退出程序（托盘图标右键 → 彻底退出），否则 Windows 会因文件被占用而打包失败。
